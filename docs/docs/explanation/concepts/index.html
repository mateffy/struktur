What is Struktur?

Struktur is a data extraction harness: a TypeScript engine that uses LLMs to turn unstructured documents into validated JSON. It operates on pre-parsed artifacts, handles chunking for large documents, runs configurable extraction strategies, validates outputs with Ajv, and merges or deduplicates results when needed.

Importantly, Struktur does not parse PDFs, HTML, or other file formats. You provide normalized artifacts (JSON DTOs with text and media slices), and Struktur handles the orchestration of LLM calls to extract structured data from them.

:::note Think of Struktur as the orchestration layer between your parsed documents and structured output. The parsing happens upstream; Struktur handles the intelligence of extraction. :::

The Extraction Pipeline

Understanding the pipeline helps you make informed decisions about strategies and configuration. Here's how data flows through Struktur:

    B --> C[Strategy]
    C --> D[Output]

        direction TB
        C1[Chunking] --> C2[LLM Calls]
        C2 --> C3[Validation + Retry]
        C3 --> C4[Merge/Dedupe]
    end
    
    C --> StrategyInternals --> D

The flow:

  1. Input: Files, text, or URLs you want to extract data from
  2. Artifacts: Normalized JSON DTOs containing parsed content
  3. Strategy: Orchestrates chunking, LLM calls, validation, and merging
  4. Output: Validated JSON matching your schema

:::note Key insight: Validation happens at two levels. First, within the strategy: each LLM call is validated and retried on failure. Second, after the strategy completes: final validation ensures the merged output is correct. :::

Artifacts: The input format

Artifacts are the core abstraction that makes Struktur file-format agnostic. An artifact is a JSON DTO containing:

  • id: Unique identifier
  • type: Artifact type (text, image, pdf, file)
  • contents[]: Array of content slices with text and media
  • metadata: Optional additional data

Why normalized input? By requiring pre-parsed artifacts, Struktur stays focused on extraction orchestration. You can use any parser you prefer (PDF.js, cheerio, mammoth, etc.) and feed the results into Struktur.

Creating artifacts:

  • CLI: --input file.pdf or --stdin
  • API: fileToArtifact(buffer, options)
  • API: urlToArtifact(url)
  • API: parseInputToArtifacts(input)

See the Artifacts reference for the complete specification.

Strategies: The orchestration

A strategy defines how extraction happens. It's not just about which LLM to use—it's about the entire orchestration: how to chunk, how to call the LLM, how to validate, and how to merge results.

Available strategies:

  • simple: Single-shot extraction for small inputs
  • parallel: Process chunks concurrently, then LLM merge
  • sequential: Process chunks in order with context preservation
  • parallelAutoMerge: Parallel with schema-aware merge + dedupe
  • sequentialAutoMerge: Sequential with schema-aware merge + dedupe
  • doublePass: Parallel pass + sequential refinement
  • doublePassAutoMerge: Double-pass with auto-merge

Why so many strategies? Different documents require different approaches. A single-page invoice needs simple extraction. A 100-page report might need parallel processing for speed. A real estate exposé with duplicate units across pages needs sequential processing with deduplication.

See the How to choose a strategy guide for decision criteria.

Validation

Validation is integrated into strategies, not a separate phase. This matters because it means every LLM output is checked and retried if invalid.

How it works:

  1. LLM generates output according to your JSON schema
  2. Ajv validates the output against the schema
  3. If invalid, errors are fed back to the LLM
  4. LLM retries with error context
  5. Most extractions converge within 2 attempts

Two-level validation:

  • Strategy-internal: Each LLM call validated with retry
  • Final: After strategy completes, output validated once more

This design ensures reliable output even when LLMs produce slightly malformed JSON or miss required fields.

Merge & Dedupe

When processing large documents, content is split into chunks. Multi-chunk strategies need to merge partial results. Merge behavior is strategy-dependent.

Merge approaches:

  • LLM merge: parallel/sequential strategies use a separate LLM call to combine partial outputs
  • Schema-aware merge: Auto-merge variants use deterministic logic: arrays concatenate, objects shallow-merge, scalars prefer new values

Deduplication:

Auto-merge strategies include two-stage deduplication:

  1. Hash-based: CRC32 hash for exact duplicates
  2. LLM-based: Semantic comparison for near-duplicates

This is particularly useful when extracting arrays (like line items or property units) that may appear on multiple pages of a document.

See the Strategies reference for strategy-specific merge and dedupe behavior.

Using Struktur: CLI vs TypeScript API

Struktur provides two interfaces for different use cases:

CLI

Best for quick one-off extractions, shell pipelines, and CI/CD scripts.

  • Quick extractions from command line
  • Shell scripting and pipelines
  • CI/CD automation
  • No code required

CLI Reference →

TypeScript API

Best for application integration, custom strategies, and production workflows.

  • Application integration
  • Custom extraction strategies
  • Production workflows
  • Fine-grained control

API Reference →

Both interfaces use the same core engine and support all strategies. Choose based on your integration needs.
