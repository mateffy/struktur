How to choose a strategy

Select the right extraction strategy for your situation. About 5 minutes.

The problem: Choosing the right strategy

You need to extract data and want the best strategy for your situation. This guide helps you decide based on your document characteristics, speed requirements, and accuracy needs.

If you're not familiar with what strategies are, read the Concepts explanation first.

Quick decision guide

Follow this decision tree:

flowchart TD
    A[Start] --> B{Input fits in context?}
    B -->|Yes| C[Use simple]
    B -->|No| D{Speed or accuracy priority?}
    D -->|Speed| E{Need deduplication?}
    D -->|Accuracy| F{Need deduplication?}
    E -->|Yes| G[Use parallelAutoMerge]
    E -->|No| H[Use parallel]
    F -->|Yes| I[Use sequentialAutoMerge]
    F -->|No| J{Cross-chunk context matters?}
    J -->|Yes| K[Use sequential]
    J -->|No| L[Use doublePass]

:::note Rule of thumb: Start with simple. If your document is too large or you need better accuracy, move up the complexity ladder. :::

Strategy comparison

StrategySpeedAccuracyContextBest for
simpleFastestGoodFullSmall docs, testing
parallelFastGoodLimitedLarge docs, speed priority
sequentialMediumBetterPreservedContext-dependent data
*AutoMergeMediumBetterVariesArrays with duplicates
doublePassSlowBestFullHigh-stakes extraction

Use simple when...

  • Your document fits within the model's context window
  • You have a simple schema without nested arrays
  • You're testing or prototyping
  • Speed is the priority
struktur --input document.txt \
  --schema schema.json \
  --model openai/gpt-4o-mini

Use parallel when...

  • Speed is your top priority
  • Chunks are relatively independent
  • You have many documents to process
  • You can accept potential loss of cross-chunk context

Trade-off: Fast but may miss relationships between distant parts of the document. Uses an LLM merge step which adds token cost.

struktur --input large-document.pdf \
  --schema schema.json \
  --strategy parallel \
  --model openai/gpt-4o-mini

Use sequential when...

  • Context between chunks matters
  • You're building data incrementally (e.g., accumulating line items)
  • Later sections reference earlier sections
  • You need better accuracy than parallel

Trade-off: Slower than parallel but maintains coherence across the document. Each chunk sees previous results.

struktur --input report.pdf \
  --schema schema.json \
  --strategy sequential \
  --model openai/gpt-4o-mini

Use auto-merge variants when...

  • You're extracting arrays that may have duplicates
  • You want to consolidate results without LLM merge cost
  • Documents have repeated information across pages
  • You need deterministic merge behavior

Best for: Invoices with line items, real estate with multiple units, catalogs with products that appear on multiple pages.

struktur --input invoice.pdf \
  --schema schema.json \
  --strategy sequentialAutoMerge \
  --model openai/gpt-4o-mini

Use double-pass when...

  • Accuracy is more important than cost
  • You're doing high-stakes extractions
  • You have complex schemas
  • You can afford two full passes

How it works: First pass runs in parallel for speed. Second pass runs sequentially with the first pass results as context for refinement. Highest quality, highest cost.

struktur --input critical-document.pdf \
  --schema schema.json \
  --strategy doublePass \
  --model openai/gpt-4o
